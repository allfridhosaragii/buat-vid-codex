## Creative strategy
Human concern (avoid sensationalizing) → engineering root problem in conditional terms → true product UI → meaningful synthetic experiment → official automation evidence → closing. The emotional movement: empathy → curiosity → clarity → surprise (FAIL/PASS) → trust → action.

Visual hierarchy: a very short headline, one technical diagram, one genuine screenshot in each proof moment, clean source footer. Never cram all at once. Max 1–2 data facts per five seconds, except a readable scoreboard. Avoid overly generic floating dashboard panels and interminable slow zooms. Visuals should explain *why* a concurrent scenario differs. Demonstrate the difference between an idempotency key check after async versus reserving the key synchronously before async.
